# CodingAgentsGO Application

**CodingAgentsGO** is an interactive multi-agent workspace for pair programming. It uses ArtifactFlow as its primary database backing layer for agent memory, run events logging, and vector stores.

## Blackboard Memory Store

Rather than managing a bespoke storage framework, CodingAgentsGO utilizes the ArtifactFlow state package to build its memory database in `main.go` of CodingAgentsGO, a separate repository:

```go
board, err := afstate.NewBlackboard("artifactflow_agents.db")
mem := memory.NewArtifactFlowStore(board)
```

The system wraps the Blackboard to store and retrieve:
*   **Vector Embeddings**: Embedding outputs generated by local embedding backends (Ollama or LM Studio) are persisted in the `vectors` table.
*   **Conversational History**: Prompt logs, agent choices, and messages are saved in the `messages` table.
*   **State configuration**: Active session variables are saved in the `configs` table.

## Cognitive Orchestration Roles

CodingAgentsGO assigns specific programming roles to agents:
*   **Analyst**: Assesses context, parses requirements, and designs system blueprints.
*   **Planner**: Formulates structured implementation files and tasks checklists.
*   **Critic**: Reviews draft implementations for logical gaps.
*   **Redteamer / Security**: Simulates exploit pathways and checks code safety (e.g. validating safetensors load policies).
*   **Coder**: Produces files and executes code changes.
*   **Synthesizer**: Combines outputs into final summaries.

## Live Dashboard and SSE Integration

CodingAgentsGO starts a local server (`http://localhost:8080`) that feeds live execution updates to a dashboard:
*   **Event Hub**: Receives events from agent loops and publishes them to outputs.
*   **Server-Sent Events (SSE)**: Streams real-time progress updates directly from the Blackboard to the browser interface.
